# Logwatch Security

Локальный анализатор SSH- и nginx-логов без сторонних зависимостей. Python 3.10+.

```sh
python3 logwatch.py examples/demo.log --year 2026
python3 logwatch.py /var/log/auth.log --year 2026 --json > report.json
python3 logwatch.py access.log --threshold 5 --window 300
python3 -m unittest discover -s tests -v
```

Выявляет серии ошибок SSH, успешный вход после ошибок с того же IP, обращения к подозрительным веб-путям и всплески HTTP-запросов. JSON содержит хронологию и исходные строки; каждый вывод ссылается на номера строк. Порог HTTP-всплеска равен threshold × 20. Окно по умолчанию — 300 секунд.

Поддерживаются стандартные SSH syslog/ISO timestamps и nginx common/combined access logs. Нераспознанные строки учитываются в skipped. Для syslog без года укажите --year; часовой пояс берётся из локального окружения. Файлы, пересекающие Новый год, предварительно разделите. Лучше анализировать каждый источник отдельно.

Срабатывание — повод для проверки, а не доказательство атаки. Общие IP, легитимные сканеры и нагрузка могут вызвать срабатывания. Проверка путей основана на небольшом наборе эвристик. Это начальная версия: файл и хронология держатся в памяти, ротация и потоковое чтение пока не реализованы. Отчёт содержит исходные логи, включая возможные чувствительные данные.

Данные никуда не отправляются.

## История изменений

- Проверка имён реальным TShark — добавлен воспроизводимый синтетический PCAP с DNS-ответом, HTTP Host и TLS ClientHello; интеграционный тест проверяет извлечение имён без обращения к внешней сети.

- Приложения и сайты — в карточках появились процессы/PID по точному локальному сокету (live, Linux/ss), наблюдаемые имена TLS SNI и HTTP Host, а также отдельные предположительные DNS-подсказки. Источник и номер пакета доступны в деталях; PCAP не сопоставляется с текущими процессами.

- Объяснения соединений — двусторонняя группировка пакетов, объём по направлениям, DNS/TLS и сбросы с доказательствами; повторные TLS-события подавлены. Добавлена эвристика 20 TCP-портов одного адреса за 10 секунд. В интерфейсе максимум 100 групп и 100 предупреждений. Отсутствие сигнала не подтверждает безопасность; домен из DNS не приписывается соседним TLS-соединениям.

- Совместимость с TShark 4.2 — логические флаги принимаются как True/False и 1/0; исправлено распознавание начала TCP-соединений, добавлена проверка формата.

- v0.1.0 — первая CLI-версия: анализ SSH и nginx, строки-доказательства, хронология JSON, демонстрационный лог и четыре теста.
- Правила работы — добавлен AGENTS.md: отдельное согласование каждого коммита, тесты после патчей и отчёт качества с уведомлением о регрессиях.
- Документирование патчей — каждый патч кратко описывается в README, чтобы история проекта была понятна.
- Живой трафик — добавлен traffic.py: потоковый разбор TShark, объяснения DNS/TCP/TLS, статистика и ограниченный кэш соединений. Общий анализатор также принимает PCAP; графический интерфейс пока не добавлен.

## Трафик в реальном времени

Установите TShark из пакетов вашей ОС и настройте разрешения захвата для dumpcap. Программа сама не повышает права. Список интерфейсов:

```sh
python3 traffic.py --interfaces
python3 traffic.py --live lo --duration 60
python3 traffic.py --live eth0 --duration 60 --filter 'tcp or udp'
python3 traffic.py --live eth0 --json
python3 traffic.py --pcap recording.pcapng
```

Замените lo/eth0 на интерфейс из списка. Ctrl+C останавливает захват. По умолчанию live ограничен 60 секундами, promiscuous mode выключен. Исходные пакеты на диск не сохраняются. --json выдаёт JSON Lines с событиями и итогами, пригодными для будущего интерфейса.

Вывод объясняет DNS-запросы, начало TCP-соединения, сбросы и TLS, с номером пакета-доказательства. Обычные пакеты одного соединения объединяются в счётчики. Это объяснение наблюдений, а не полноценный детектор сетевых атак. TLS определяется по полю протокола, а не по порту 443; HTTPS не расшифровывается. Кэш ограничен 4096 соединениями: evicted_flows показывает вытеснения, tracked_flows не является общим числом соединений за сессию. non_ip и malformed показывают ограничения покрытия. Статистика байтов относится к длинам кадров, а не к полезной нагрузке приложения. Поддерживаются IP/IPv6, TCP/UDP; вложенные туннели разбираются по первому значению поля.

Документация TShark: https://www.wireshark.org/docs/man-pages/tshark.html

## Локальный интерфейс

```sh
python3 dashboard.py
```

Откроется браузер с двумя режимами: живой захват (интерфейс и длительность) и загрузка PCAP/PCAPNG до 64 МиБ. Кнопка «Остановить» завершает текущую обработку. Счётчики обновляются во время анализа; события раскрываются в объяснение, адреса и номер пакета. В памяти остаются последние 300 событий. Временный PCAP удаляется после обработки; при аварийном завершении процесса временный файл может остаться в системной временной папке.

Сервер слушает только 127.0.0.1 на случайном порту. Требуются TShark и права dumpcap. Если приложение ещё не получило группу wireshark после установки, запустите `sg wireshark -c 'python3 dashboard.py'`. Закрытие вкладки не останавливает захват: используйте «Остановить» или Ctrl+C в терминале сервера.

### Как определяются приложения и сайты

- В веб-интерфейсе живого захвата Linux-команда `ss` раз в 0,5 секунды считывает процессы, видимые текущему пользователю. Сопоставляется полная пара адресов/портов и протокол; сведения должны быть не старше 2 секунд относительно пакета. Нет запросов sudo, чтения командных строк процессов или внешнего сервиса определения IP. Имена процессов — не названия вкладок или брендов. Короткие соединения, неприсоединённый UDP, wildcard-сокеты, чужие процессы и другой сетевой namespace могут остаться неизвестными. Подпись — наблюдение около времени пакета, не доказательство владельца каждого пакета; повторное использование сокета возможно.
- TLS SNI и HTTP Host берутся из самого потока с указанием пакета. Они показывают заявленное имя, но не подтверждают сайт или его безопасность. При ECH может быть видно только внешнее имя; если handshake отсутствует, имени может не быть. Для HTTPS не видны URL и содержимое запросов.
- DNS-подсказка — только для успешного ответа с одной A/AAAA-записью, совпадающим именем владельца и вопроса, тем же клиентом и адресом назначения; действует не дольше TTL или 60 секунд. Запрос без ответа не используется. Цепочки CNAME и ответы с несколькими адресами пока пропускаются. Несколько кандидатов отображаются отдельно, а не превращаются в уверенное название сайта. Подсказка относится ко времени последнего пакета группы; собственных DNS-запросов анализатор не делает.
- В PCAP доступны имена из пакетов, но процессы всегда неизвестны: текущая таблица сокетов для записей не используется. CLI сохраняет прежний вывод событий; новые карточки доступны в веб-интерфейсе.
